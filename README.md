# Хакатон «Довезти кубик»

Прошивка мобильного робота на меканум-колёсах (ESP32): робот сам доезжает до манипулятора,
останавливается, по UDP просит погрузить кубик, ждёт окончания погрузки и везёт кубик в зону разгрузки.

## Задача

| № | Этап | Что делает робот | Этап выполнен, если |
|---|------|------------------|---------------------|
| 01 | Старт | Программа запускается сама при включении питания, без ноутбука и ручных команд | Робот тронулся без участия команды |
| 02 | Подъезд | Едет из зоны старта к манипулятору: вперёд, вбок, по диагонали | Робот в зоне манипулятора и ни с чем не столкнулся |
| 03 | Остановка | Встаёт багажником под манипулятор и выключает все моторы | Багажник целиком внутри разметки зоны |
| 04 | Запрос погрузки | Подключается к Wi-Fi ROBOT_ARM и отправляет LOAD. Нет STARTED за 3 с — отправляет LOAD снова | Манипулятор ответил STARTED и начал погрузку |
| 05 | Ожидание | Стоит неподвижно, пока манипулятор кладёт кубик (~14 с). Ждёт DONE не дольше 30 с | Получен DONE, кубик в багажнике |
| 06 | Доставка | После DONE сам едет в зону разгрузки и останавливается в ней | Робот целиком в зоне, кубик в багажнике |

Правила: две попытки по 3 минуты, в зачёт лучшая; касаться робота нельзя. Оценивается последний коммит.

### Критерии (известная часть)

- **A. Перемещение — 20:** автономный запуск 3, плавность 3, прямолинейность 3, движение вбок 3,
  сложный манёвр (диагональ или разворот) 3, без столкновений 2, повторяемость 3.
- **B. Остановка — 15:** доезд 5, багажник в зоне 7 (частично — 3), моторы выключены до LOAD 3.
- **C. Обмен по UDP — 20:** подключение 4, LOAD → STARTED 6, неподвижность до DONE 5,
  надёжность 5 (повтор LOAD — 3, таймаут DONE — 2).

Где это закрыто в коде:

| Критерий | Как |
|---|---|
| Автономный запуск | Программа стартует сама, через 3 с после включения робот едет (`START_DELAY_MS`) |
| Плавность | Без ШИМ разгона нет; импульсный режим `PULSE_ON_MS` / `PULSE_OFF_MS` снижает скорость, пауза `PAUSE_MS` между отрезками убирает заносы |
| Прямолинейность | Курс не меняется за всю поездку, направление каждого колеса выставлено `dir` |
| Движение вбок | Отрезки 0, 6, 8 маршрута |
| Сложный манёвр | Зигзаг 1–4: диагонали под 45° |
| Моторы выключены до LOAD | `motorsOff()` после полной остановки, только потом `REQ_LOAD` |
| Повтор LOAD | LOAD каждые 3 с, пока не придёт STARTED или BUSY (`LOAD_RETRY_MS`) |
| Таймаут DONE | Через 30 с без DONE робот всё равно едет на доставку (`DONE_TIMEOUT_MS`) |
| Неподвижность | В `REQ_LOAD` и `WAIT_DONE` моторы не управляются вообще |

## Железо

- Плата **ESP32 Dev Module**, Arduino IDE / `arduino-cli`, ядро «esp32 by Espressif» любой версии.
- **ШИМ не используется:** моторы управляются только `digitalWrite` — колесо крутится вперёд, назад или стоит.
- **Питание ESP32 от аккумулятора:** 5V с L298N (перемычка 5V-EN стоит) идёт на **VIN** ESP32, GND — на GND.
  Не на 3V3! Без этого провода плата работает только от USB — «без провода робот не едет».
- Защита ESP32 от просадки питания (brownout) отключена в `setup()`: иначе при старте моторов от аккумулятора
  плата перезагружается.
- **Синий светодиод на плате (GPIO2)** показывает состояние и без USB: часто мигает — стартовая пауза,
  горит — едет, медленно мигает — у манипулятора, погас — финиш. Не мигает вообще — программа не запущена.
- При старте в Serial Monitor (115200) печатается `[BOOT] … причина: …`.
- Шасси с четырьмя меканум-колёсами, питание — два 18650 через XT60. От USB моторы не крутятся.
- Драйверы моторов — два **L298N**, перемычки ENA/ENB стоят, на входы IN подаётся HIGH / LOW.

| Мотор | Драйвер | IN1 | IN2 |
|---|---|---|---|
| 1 · передний левый | L298N №2, IN1/IN2 | 26 | 25 |
| 2 · передний правый | L298N №2, IN3/IN4 | 33 | 32 |
| 3 · задний левый | L298N №1, IN3/IN4 | 16 | 4 |
| 4 · задний правый | L298N №1, IN1/IN2 | 18 | 17 |

IN1 = HIGH, IN2 = LOW — вращение в одну сторону, IN1 = LOW, IN2 = HIGH — в другую, оба LOW — стоп.
Пины меняются в `robot_cube/motion.h` (таблица `motors`) и так же в `tools/motor_test/motor_test.ino`.

## Протокол UDP

Wi-Fi **ROBOT_ARM**, пароль **12345678**. Манипулятор **192.168.4.1:4210**, ответ приходит на адрес и порт отправителя.

| Запрос | Ответ | Смысл |
|---|---|---|
| PING | PONG | Проверка связи |
| STATUS | IDLE / BUSY | Манипулятор свободен / занят |
| LOAD | STARTED → DONE | Погрузка ~14 с, DONE приходит до 3 раз |
| LOAD повторно | BUSY | Погрузка уже идёт |

Ответы робот обрезает от пробелов и `\r\n` и приводит к верхнему регистру. Нужен ли манипулятору
перевод строки в конце команды — проверить с ноутбука через `net/net.py`: отправить `PING`, должен прийти `PONG`.
Если ответа нет — в `sendCmd()` после `udp.print(cmd);` добавить `udp.print("\n");` и проверить робота снова.

## Маршрут

Робот **ни разу не поворачивается**: курс постоянный, меканум едет в любую сторону.
Маршрут записан в `route.h` строками `{ вид движения, метры, k }`.

**Постановка на старт:** дальний конец отрезка 2,25 м, лицом вдоль зигзага и отрезка 2,38 м
(не вдоль линии 2,25 м). Перёд робота — там, где мотор 1 (передний левый). Отметить перёд скотчем.

```
 S ●  старт
   │
   │  2,25 м — вбок вправо
   │
 J ●╲  ╱╲  ╱─────── 2,38 м ───────● P
     ╲╱  ╲╱                       │
    зигзаг 4 × 1,11 м под 45°     │  3,6 м — вбок вправо
                                  │
           B ●──── 2,13 м назад ───● M  манипулятор
             │
             │  2,33 м — вбок вправо
             │
           U ●  зона разгрузки

   курс робота всё время →, «вправо» на схеме — вниз
```

| № | Участок | Движение в `route.h` | Метры |
|---|---|---|---|
| 0 | Старт → начало зигзага | `GO_RIGHT` | 2,25 |
| 1 | Зигзаг | `GO_FWD_RIGHT` | 1,11 |
| 2 | Зигзаг | `GO_FWD_LEFT` | 1,11 |
| 3 | Зигзаг | `GO_FWD_RIGHT` | 1,11 |
| 4 | Зигзаг | `GO_FWD_LEFT` | 1,11 |
| 5 | Прямо | `GO_FWD` | 2,38 |
| 6 | Вбок к манипулятору (замер 3,71, укорочено до 3,6) | `GO_RIGHT` | 3,6 |
| — | *погрузка* | | |
| 7 | Назад | `GO_BACK` | 2,13 |
| 8 | Вбок в зону разгрузки | `GO_RIGHT` | 2,33 |

Геометрия восстановлена по AR-замерам, углы зигзага и перпендикулярность отрезков стоит проверить рулеткой.

## Архитектура

```
robot_cube/
├── robot_cube.ino   конечный автомат попытки и UDP
├── motion.h         пины, моторы, виды движения, скорости, импульсы, пересчёт метров во время
└── route.h          маршрут — главный файл подгонки на поле
net/
└── net.py           консоль для ручной проверки манипулятора с ноутбука
tools/
├── motor_test/      проверка моторов: каждое колесо по очереди, без остальной программы
└── mock_arm/        имитатор манипулятора на запасном ESP32
```

**Конечный автомат** (`robot_cube.ino`):

`WAIT_START` (3 с) → `TO_ARM` (маршрут к манипулятору) → моторы выключены → `REQ_LOAD`
(LOAD каждые 3 с до STARTED или BUSY) → `WAIT_DONE` (до DONE или 30 с) → `TO_UNLOAD` → `FINISHED`.

Решения:

- **Без ШИМ.** Каждое колесо: вперёд, назад или стоп (`digitalWrite`). Вид движения задаёт, какие колёса
  куда крутятся (таблица `WHEELS` в `motion.h`): вперёд/назад — все четыре, вбок — пары навстречу,
  диагональ — только одна диагональная пара колёс.
- **Отрезки в метрах.** Время отрезка = метры / скорость этого вида движения × `k`. Скоростей три,
  все калибруются на полу: `SPEED_FWD`, `SPEED_SIDE`, `SPEED_DIAG`.
- **Скорость снижается импульсами:** моторы `PULSE_ON_MS` включены, `PULSE_OFF_MS` выключены.
  `PULSE_OFF_MS = 0` — полная скорость. Это по сути медленный программный ШИМ: если его нельзя — ставить 0.
- **Пауза `PAUSE_MS`** между отрезками: робот полностью останавливается и не заносит при смене направления.
- **BUSY на повторный LOAD** — STARTED потерялся, погрузка уже идёт → ждём DONE.
- **DONE раньше STARTED/BUSY** — все ответы на LOAD потерялись, погрузка уже закончилась → сразу едем на доставку,
  а не запускаем вторую погрузку.
- **Таймаут DONE** — через 30 с робот всё равно едет на доставку.
- **Wi-Fi** включается, когда робот доехал до манипулятора и моторы стоят: на старте радио и моторы вместе
  тянут большой ток. Если связи нет 10 с, подключение начинается заново (`WIFI_KICK_MS`).
- Каждый отрезок можно подогнать множителем времени `k` в `route.h`.

**Режимы отладки** (флаги вверху `robot_cube.ino`):

| Флаг | Что делает |
|---|---|
| `WHEEL_TEST 1` | Каждое колесо по очереди, по кругу, крутится «вперёд» 1,5 с, в мониторе номер мотора и пины |
| `CALIB_TEST 1` / `2` / `3` | Едет «2 м» вперёд / вбок / по диагонали и стоп — для калибровки скоростей |
| `TUNE_STEPS N` | Проезжает только первые N отрезков маршрута к манипулятору и стоп |

Кто где работает: связь — `robot_cube.ino`, движение — `motion.h`, маршрут — `route.h`.

## Сборка и прошивка

> **Безопасность:** после заливки программа стартует сама и через 3 с робот поедет, если подключён аккумулятор.
> Пока робот на USB — колёса должны висеть в воздухе.

```bash
arduino-cli config add board_manager.additional_urls https://espressif.github.io/arduino-esp32/package_esp32_index.json
arduino-cli core update-index
arduino-cli core install esp32:esp32
arduino-cli board list
arduino-cli compile --fqbn esp32:esp32:esp32 robot_cube
arduino-cli upload  -p <PORT> --fqbn esp32:esp32:esp32 robot_cube
arduino-cli monitor -p <PORT> -c baudrate=115200
```

Arduino IDE: Boards Manager → «esp32 by Espressif Systems» → Board: ESP32 Dev Module → Upload → Serial Monitor 115200.
Заливка зависла на `Connecting.....` — зажать BOOT. Нет порта — кабель только для зарядки или нет драйвера CH340 / CP2102.

## План проверки на поле

1. **Сухой прогон без аккумулятора** (XT60 отключён, только USB). В мониторе: `WAIT_START` → `TO_ARM` →
   `[ROUTE] отрезок 0…6` → `REQ_LOAD` → `[WIFI] подключено` → `-> LOAD`, `<- STARTED`, `<- DONE` → `TO_UNLOAD` → `FINISHED`.
   Рядом с манипулятором или с `tools/mock_arm` (у него `DROP_FIRST_LOAD 1` — проверка повтора).
2. **Моторы и проводка** (`tools/motor_test`, на подставке, аккумулятор подключён). Каждый мотор крутится
   вперёд и назад; в мониторе видно, какой мотор сейчас должен крутиться.
   Не крутится ничего — проверить питание L298N, общий GND с ESP32 и перемычки ENA/ENB.
3. **Колёса** (`WHEEL_TEST 1`, на подставке, аккумулятор подключён). Первым крутится мотор 1 — передний левый.
   Колесо, которое крутится назад, — `dir = -1` в `motion.h`.
4. **Маршрут на подставке** (обычный режим). Первый отрезок — вбок вправо: передний левый и задний правый
   крутятся вперёд, два других — назад. На зигзаге крутится только одна диагональная пара, вторая стоит.
   Если на полу при `GO_RIGHT` робот едет влево — в `WHEELS` в `motion.h` поменять местами строки
   `GO_RIGHT` ↔ `GO_LEFT`, `GO_FWD_RIGHT` ↔ `GO_FWD_LEFT`, `GO_BACK_RIGHT` ↔ `GO_BACK_LEFT`.
5. **Скорость и калибровка на полу.** Слишком быстро — увеличить `PULSE_OFF_MS` в `motion.h`.
   Потом `CALIB_TEST 1`: измерить реальное расстояние d, `SPEED_FWD = SPEED_FWD * d / 2.0`.
   `CALIB_TEST 2` — то же для `SPEED_SIDE`, `CALIB_TEST 3` — для `SPEED_DIAG` (d по прямой от старта до финиша).
6. **Подгонка по кускам.** `TUNE_STEPS 1` — только 2,25 м, `5` — старт + зигзаг, `7` — весь путь до манипулятора.
   Недоезжает — увеличить `k` отрезка (например, 1.05).
7. **Автономный старт.** USB отключён, только аккумулятор: на ESP32 горит красный светодиод питания,
   синий часто мигает 3 с, потом робот едет. Красный не горит — нет провода 5V L298N → VIN ESP32.
8. **Полный прогон** с манипулятором — несколько раз подряд.

## Риски и открытые вопросы

- Нужен ли `\n` в командах UDP (проверить `net/net.py`).
- Не откалиброваны `SPEED_FWD`, `SPEED_SIDE`, `SPEED_DIAG`, `dir`; после смены импульсов калибровать заново.
- Без ШИМ нет плавного разгона, а скорость каждого колеса не подстроить: если робота уводит, поможет только
  поправка `k` и точная постановка на старт.
- Езда по времени зависит от заряда: калибровать на заряженных аккумуляторах и перепроверять перед попыткой.
- Вбок робот едет ~8,2 м из ~16 м — на глянцевом полу ролики проскальзывают, `SPEED_SIDE` критичен.
- Колонна у начала зигзага (точка J) — проверить, что робот её не задевает.
- Проверить, где багажник и попадает ли он под манипулятор; при необходимости подогнать отрезок 6.
- Если манипулятор вообще не отвечает, робот так и стоит в `REQ_LOAD` (по ТЗ доставка — только после DONE).
- За 15–20 минут до конца заморозить рабочую версию: оценивается последний коммит.
